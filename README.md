# mdread

Локальный ридер Markdown на C++17. Открывает файл или папку в отдельном окне
приложения и обновляет документ после сохранения в редакторе.

```sh
mdread notes.md
mdread ./docs
```

[Установка](#установка) · [Использование](#использование) · [Технологии](#технологии) · [Сборка и тесты](#сборка-и-тесты)

## Возможности

| Возможность | Что доступно |
| --- | --- |
| Просмотр Markdown | Заголовки, списки, таблицы, цитаты, ссылки, изображения, блоки кода и списки задач |
| Браузер файлов | Папки и подпапки, поиск по именам в текущей папке, переходы назад и вперёд |
| Автообновление | Обновление документа и списка файлов; поддержка атомарного сохранения редактором |
| HTML в Markdown | Таблицы, `details`, `sub` / `sup`, ссылки, изображения и встроенное оформление через `style` |
| Формулы | Формулы LaTeX в `$...$` и `$$...$$`, включая `aligned`, матрицы, дроби и индексы |
| Интерфейс | Светлая, тёмная и системная темы; скрываемая панель файлов с изменяемой шириной |
| Навигация macOS | Нативные жесты трекпада для перехода назад и вперёд |

Поддерживаются расширения `.md` и `.markdown` без учёта регистра. В списке папки
идут перед файлами; скрытые имена с точкой не показываются. Большие списки
разбиты на страницы по 100 записей.

## Платформы

| Платформа | Окно приложения | Статус |
| --- | --- | --- |
| macOS | AppKit + WKWebView | Сборка, HTTP- и оконные проверки выполнены локально |
| Linux | GTK 3 + WebKitGTK | Реализация и конфигурация CI есть; локальный Linux-прогон пока не выполнен |
| Windows | — | Не поддерживается |

Проект собирается из исходников. Результаты проверок и их ограничения описаны
в [отчёте по исправлениям](docs/review_resolution.md).

## Установка

### macOS: быстрый старт

```sh
git clone https://github.com/1gwardi/md_reader.git
cd md_reader
./mac_setup.zsh
```

Установщик проверяет Command Line Tools и macOS SDK, устанавливает Homebrew
при необходимости, затем недостающие `cmake`, `pkgconf` и `md4c`.
Запускайте его от обычного пользователя, без `sudo`.

Если открылся установщик Command Line Tools, завершите установку в окне Apple
и повторите `./mac_setup.zsh`. При первой установке Homebrew может понадобиться
пароль администратора. Для загрузки зависимостей нужен интернет.

| Результат установки | По умолчанию |
| --- | --- |
| Каталог Release-сборки | `build/macos` |
| Команда `mdread` | `~/.local/bin/mdread` |
| Настройка `PATH`, если каталога в нём ещё нет | `~/.zshrc` или `$ZDOTDIR/.zshrc` |

После установки откройте новый терминал:

```sh
mdread .
```

Для уже открытого терминала установщик напечатает команду настройки `PATH`,
если она нужна. Повторный запуск обновляет сборку и не дублирует настройку zsh.

| Опция `mac_setup.zsh` | Назначение |
| --- | --- |
| `--build-only` | Установить зависимости и собрать, не устанавливая бинарник |
| `--prefix ПУТЬ` | Изменить каталог установки |
| `--build-dir ПУТЬ` | Изменить каталог сборки |
| `--no-path` | Установить без изменения настроек zsh |
| `-h`, `--help` | Показать справку |

Относительные пути в опциях считаются от текущей рабочей папки.
После `--build-only` бинарник по умолчанию находится в `build/macos/mdread`.

### Linux: сборка из исходников

Зависимости для Ubuntu 24.04 / Debian с пакетами WebKitGTK 4.1:

```sh
sudo apt update
sudo apt install build-essential cmake pkg-config \
  libmd4c-dev libmd4c-html0-dev libgtk-3-dev libwebkit2gtk-4.1-dev
```

В новых выпусках Debian вместо `libmd4c-html0-dev` используется
`libmd4c-html-dev`. Затем из корня репозитория:

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=OFF
cmake --build build --parallel 2
./build/mdread examples/demo.md
```

Для команды без пути установите бинарник и добавьте его каталог в `PATH`:

```sh
cmake --install build --prefix "$HOME/.local"
export PATH="$HOME/.local/bin:$PATH"
mdread .
```

Строку `export PATH=...` можно сохранить в настройках своей оболочки.
Для окна приложения нужен графический сеанс; для режима сервера есть `--no-window`.

## Использование

| Команда | Действие |
| --- | --- |
| `mdread notes.md` | Открыть один документ |
| `mdread .` | Просматривать текущую папку |
| `mdread "/путь/к/заметкам"` | Открыть папку, в том числе с пробелами в пути |
| `mdread --offline notes.md` | Запретить автоматическую загрузку внешних изображений |
| `mdread --no-window notes.md` | Запустить только локальный сервер и вывести URL |
| `mdread --port 8080 notes.md` | Указать порт вместо автоматически выбранного |
| `mdread -- --file.md` | Открыть файл, имя которого начинается с дефиса |
| `mdread --help` | Показать справку |

Опции можно сочетать. `--no-browser` сохранён как синоним `--no-window`.
Закрытие окна завершает ридер и его сервер. Из терминала остановить программу
можно через `Ctrl+C`.

### Управление в окне

| Элемент | Действие |
| --- | --- |
| Стрелки назад / вперёд | Перемещение по истории открытых страниц |
| Кнопки папки и корня | Возврат к папке документа или в корень открытой директории |
| Поиск, `Cmd+K` / `Ctrl+K` | Фильтрация имён файлов и подпапок текущей папки |
| Кнопка списка файлов | Скрыть или показать боковую панель |
| Правая граница панели | Перетащить для изменения ширины; двойной щелчок сбрасывает размер |
| `Tab`, затем стрелки / `Home` / `End` на границе | Изменить ширину панели с клавиатуры |
| «Обновить» | Вручную перечитать документ и список |
| Кнопка темы | Выбрать светлую, тёмную или системную тему |
| `Esc` или нажатие вне панели | Закрыть список файлов в узком окне |
| `Cmd+W` / `Cmd+Q` на macOS | Закрыть окно / завершить приложение |

Тема, ширина панели и запрос поиска сохраняются при переходах внутри текущей
сессии. Подсказки кнопок появляются при наведении курсора. Жесты трекпада на
macOS используют системную настройку «Смахивание между страницами».

## Форматирование и примеры

| Пример | Запуск |
| --- | --- |
| Markdown: списки, таблицы и код | `mdread examples/demo.md` |
| HTML, встроенные стили и раскрывающиеся блоки | `mdread examples/html.md` |
| Формулы и преобразования координат | `mdread examples/formulas.md` |

Формулы в тексте записываются как `$x_0 + y_0$`, отдельные блоки — через `$$`:

```tex
$$
\begin{aligned}
x &= x_0 + d \cdot \cos(\theta) \\
y &= y_0 + d \cdot \sin(\theta)
\end{aligned}
$$
```

В `aligned` строки разделяются `\\`. Совместимость с Markdown-экспортерами
позволяет писать `$d\_{\text{fwd}}$` вместо `$d_{\text{fwd}}$`; подчёркивания
в текстовых названиях вроде `\text{view\_max}` сохраняются. Поддерживается синтаксис
KaTeX, а не произвольный документ LaTeX. В блоках кода формулы остаются текстом.

HTML можно смешивать с Markdown. Для Markdown внутри блочного HTML оставляйте
пустые строки между тегами и текстом. Скрипты, обработчики событий, iframe
и глобальные `<style>` удаляются; для оформления используйте `style="…"`.

Относительные изображения и ссылки считаются от папки документа. При запуске
с директорией ссылки на соседние Markdown-файлы открываются в том же окне.
Изменение самого изображения видно после обновления Markdown или нажатия «Обновить».

## Сборка и тесты

Для ручной сборки на macOS установите зависимости через `brew install cmake pkgconf md4c`
и убедитесь, что доступны Command Line Tools. Команды ниже выполняются из корня
репозитория. Для тестов нужны Python 3.9+ и доступ к локальным TCP-портам.

| Режим | Опции CMake |
| --- | --- |
| Обычная сборка | `-DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=OFF` |
| HTTP- и вспомогательные тесты | `-DBUILD_TESTING=ON` |
| Оконные тесты macOS | `-DBUILD_TESTING=ON -DMDREAD_TEST_NATIVE_WINDOW=ON` |
| AddressSanitizer + UndefinedBehaviorSanitizer | `-DCMAKE_BUILD_TYPE=Debug -DMDREAD_SANITIZERS=ON` |

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=ON
cmake --build build --parallel 2
ctest --test-dir build --output-on-failure
```

Оконным тестам нужен графический сеанс macOS. `mac_setup.zsh` отключает тесты
в своём каталоге сборки. Параметры CMake сохраняются в кэше: при повторной настройке
явно меняйте нужные опции. Конфигурация CI для macOS/Linux находится в
[checks.yml](.github/workflows/checks.yml); результаты локальных проверок — в
[отчёте](docs/review_resolution.md).

## Ограничения и доступ к файлам

| Ограничение | Поведение |
| --- | --- |
| Граница доступа | Открытая директория или папка одиночного файла; симлинки внутри корня не поддерживаются |
| Размер исходника / изображения | До 16 MiB на файл |
| Сложность документа | До 4 MiB HTML и 60 000 DOM-узлов; более сложный документ показывает ошибку в оболочке |
| Формулы | До 200 выражений; ошибочная или слишком сложная формула остаётся текстом |
| Автообновление | Пауза между опросами — 0.6–2 секунды; фоновый опрос приостановлен; ошибки замедляют повторные запросы |
| Пока отсутствует | Редактирование Markdown, подсветка синтаксиса, печать и экспорт |

Документы отображаются без изменения исходных файлов. Внешние изображения
по умолчанию разрешены; `--offline` запрещает их автоматическую загрузку.
Библиотеки, стили и математические шрифты ридера работают без внешних сервисов.

Локальный сервер слушает `127.0.0.1` и **не имеет аутентификации**. Другие процессы
машины с доступом к порту могут запросить открытые документы. Модель доступа,
HTML/CSS и режим `--offline` подробно описаны в [docs/security.md](docs/security.md),
ресурсные бюджеты — в [docs/review_resolution.md](docs/review_resolution.md).
