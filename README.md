# mdread

Ридер Markdown-файлов и директорий на C++17 для macOS и Linux.

```sh
mdread notes.md
mdread ./docs
```

Команда открывает документ в отдельном окне приложения без адресной строки и вкладок.
После сохранения файла содержимое обновляется автоматически:
ридер проверяет изменения раз в 600 мс и сохраняет позицию прокрутки.
Закрытие окна завершает программу вместе с локальным сервером.
На macOS также работают `Cmd+W`, `Cmd+Q` и копирование текста через `Cmd+C`.
Остановка из терминала — `Ctrl+C`.

Если передать директорию, приложение откроет список её Markdown-файлов и подпапок.
Нажатие на файл открывает документ справа, на папку — её содержимое. В боковой
панели виден текущий путь, есть переход на уровень выше и в корень открытой директории.
Выбранный файл подсвечивается, заголовок окна показывает его имя.

Верхняя панель содержит кнопки «Назад», «Вперёд», перехода к папке документа
и в корень. Наведите курсор на значок, чтобы увидеть подсказку.
На macOS переходы назад и вперёд также доступны штатным горизонтальным жестом
двух пальцев на трекпаде. Он использует системную настройку «Смахивание между страницами»
и ту же историю, что кнопки; обычная прокрутка текста остаётся у WebKit.
Кнопка списка файлов скрывает боковую панель и освобождает место для чтения.
Ширина панели меняется перетаскиванием её правой границы и сохраняется при переходах.
Двойной щелчок по границе возвращает стандартную ширину. Границу можно выбрать
клавишей `Tab` и менять ширину стрелками; `Home` / `End` задают минимум и максимум.
В узком окне список открывается поверх документа; закрыть его можно кнопкой,
нажатием вне панели или клавишей `Esc`.

Поиск в боковой панели фильтрует файлы и подпапки текущей папки.
`Cmd+K` (или `Ctrl+K`) открывает панель и переводит курсор в поиск.
Запрос сохраняется при переходах внутри открытой сессии.
Кнопка «Обновить» вручную перечитывает документ и список, а зелёный индикатор
показывает работу автообновления. Если файл недоступен, появится сообщение с ошибкой.
Кнопка темы последовательно выбирает светлую, тёмную и системную тему;
выбор сохраняется при переходах между документами.

Список файлов и открытый документ обновляются автоматически. Поддерживаются
`.md` и `.markdown` без учёта регистра расширения. Папки показаны перед файлами;
скрытые имена, начинающиеся с точки, не отображаются. Пустую папку тоже можно открыть.

На macOS окно использует системные AppKit и WKWebView, на Linux — GTK 3 и WebKitGTK.
Разбор Markdown, CLI и локальный сервер написаны на C++17; системный интерфейс
macOS подключён небольшим модулем Objective-C++. Сервер слушает только `127.0.0.1`
на автоматически выбранном свободном порту. Внешние ссылки открываются
в браузере по умолчанию, оставляя документ в окне ридера.

## Сборка

На macOS можно установить зависимости, собрать и установить ридер одной командой
из корня репозитория:

```sh
./mac_setup.zsh
```

Скрипт проверяет компилятор и macOS SDK, при необходимости устанавливает
[Homebrew через официальный установщик](https://docs.brew.sh/Installation.html),
а затем недостающие пакеты `cmake`, `pkgconf` (pkg-config) и `md4c`.
Если Command Line Tools ещё нет, откроется установщик Apple. Завершите его работу
и повторите запуск скрипта. Запускайте скрипт от обычного пользователя;
установщик Homebrew сам запросит пароль, если он нужен.

Release-сборка создаётся в `build/macos`, а `mdread` устанавливается в `~/.local/bin`.
Если каталога установки ещё нет в `PATH`, скрипт добавляет его в `~/.zshrc`
(или `$ZDOTDIR/.zshrc`). Настройка сохраняет существующее содержимое файла
и не дублируется при повторной установке. Это обычный установленный исполняемый
файл, без алиасов и зависимости от текущего каталога проекта.

После установки откройте новый терминал и запускайте из любой папки:

```sh
mdread .
mdread "/путь/к/файлу.md"
```

Для текущего терминала скрипт напечатает команду `export PATH=...; rehash`,
если она необходима: дочерний процесс не может изменить окружение уже открытой оболочки.

Параметры установки:

```sh
./mac_setup.zsh --build-only                   # Только зависимости и сборка
./mac_setup.zsh --prefix "$HOME/Applications/mdread"
./mac_setup.zsh --build-dir "build/custom"     # Свой каталог сборки
./mac_setup.zsh --no-path                     # Установить без изменения настроек zsh
./mac_setup.zsh --help
```

Относительные пути в параметрах считаются от текущего рабочего каталога;
исходники скрипт находит рядом с собой. После `--build-only` запуск по умолчанию:
`./build/macos/mdread .`. Скрипт можно запускать повторно: установленные зависимости
используются повторно, а CMake обновляет сборку. При ошибке последующие шаги
не выполняются. Для первой установки зависимостей нужен доступ в интернет.

### Ручная сборка

Нужны C++17, CMake 3.16+ и [MD4C](https://github.com/mity/md4c).
На macOS нужны Command Line Tools (`xcode-select --install`), которые включают
системные SDK AppKit/WebKit. Дополнительная GUI-библиотека не требуется.
Во время работы программы интернет не требуется, стили и скрипт поставляются вместе с ней.

macOS (Homebrew):

```sh
brew install cmake md4c
```
Сборка на вашей машине: 

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
./build/mdread examples/demo.md
```

Debian / Ubuntu:

```sh
sudo apt install build-essential cmake pkg-config libmd4c-dev libmd4c-html0-dev libgtk-3-dev libwebkit2gtk-4.1-dev
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
./build/mdread examples/demo.md
```

В новых выпусках Debian пакет заголовков HTML-рендерера называется
[`libmd4c-html-dev`](https://packages.debian.org/sid/libmd4c-html-dev)
вместо `libmd4c-html0-dev`.

Для команды `mdread` без пути установите бинарник в `~/.local/bin`:

```sh
cmake --install build --prefix "$HOME/.local"
export PATH="$HOME/.local/bin:$PATH"
mdread examples/demo.md
```

Строку `export PATH=...` можно добавить в `~/.zshrc` или `~/.bashrc`.
На macOS сборка проверена; Linux поддерживается исходным кодом, но пока не проверялся.

## Использование

```sh
mdread "путь/заметка с пробелами.md"
mdread .                             # Просматривать текущую директорию
mdread "путь/папка с заметками"        # Выбрать файл внутри приложения
mdread --no-window notes.md           # Только сервер, без графического окна
mdread --port 8080 notes.md           # Выбрать порт вручную
mdread -- --file.md                   # Имя файла начинается с дефиса
mdread --help
```

`--no-window` подходит для запуска без графического сеанса и печатает локальный URL.
Старое имя этой опции, `--no-browser`, сохранено как синоним.

Поддерживаются заголовки, ссылки, изображения, цитаты, списки, таблицы,
зачёркивание, списки задач и блоки кода. Есть светлая и тёмная темы
по системным настройкам. Заголовкам назначаются якоря: `## Мой раздел` → `#мой-раздел`.
Подсветка синтаксиса пока не реализована.

## Математические формулы

Формулы LaTeX поддерживаются в тексте через `$...$` и отдельным блоком через
`$$...$$`. Например, `$x_0 + y_0$` или:

```tex
$$
\begin{aligned}
x &= x_0 + d \cdot \cos(\theta) \\
y &= y_0 + d \cdot \sin(\theta)
\end{aligned}
$$
```

В `aligned` перенос строки записывается как `\\` — два обратных слеша.
Для совместимости с Markdown-экспортерами поддерживается и экранированный
индекс: `$d\_{\text{standoff}}$` отображается так же, как `$d_{\text{standoff}}$`.
Внутри текстовых команд, например `\text{view\_max}`, подчёркивание остаётся
обычным символом. Исходный файл при отображении не переписывается.
Формулы, матрицы, дроби, индексы и математические функции отображаются встроенным
[KaTeX 0.19.1](https://katex.org/). Его стили и шрифты поставляются в бинарнике;
интернет и дополнительная установка TeX не требуются.

```sh
mdread examples/formulas.md
```

Формулы обновляются после сохранения файла. Длинные выражения прокручиваются
внутри блока и не растягивают окно. Ошибка LaTeX показывается исходным текстом
с подсказкой, остальные формулы продолжают работать. В блоках кода и обратных
кавычках формулы остаются текстом; обычный знак доллара можно записать как `\$`.

Относительные пути изображений считаются от папки открытого файла:
`![Схема](images/diagram.png)`. Доступны PNG, JPEG, GIF, WebP, SVG, AVIF и ICO
внутри открытой директории. В режиме одного файла граница доступа — его папка,
в режиме директории — директория, переданная команде.
В режиме директории ссылки на другие Markdown-файлы, например
`[Введение](../intro.md)`, открываются в том же окне. Переходы через `..` разрешены
внутри открытой директории. Выход за её пределы, включая симлинки наружу, запрещён.
Изменение самого изображения отобразится при следующем обновлении Markdown
или ручном обновлении страницы.

Файл перечитывается по содержимому, поэтому сохраняется поддержка редакторов,
которые заменяют файл целиком при сохранении. Если файл временно недоступен,
страница сохраняет последний текст и возобновляет обновления, когда файл появится.
Максимальный размер Markdown и каждого локального изображения — 16 MiB.

## HTML внутри Markdown

HTML-разметка отображается вместе с Markdown: `<div>`, `<span>`, `<br>`,
`<sub>`, `<sup>`, `<mark>`, `<details>` / `<summary>`, HTML-таблицы,
ссылки `<a>` и изображения `<img>`. Атрибут `style` поддерживает встроенный CSS,
например `<span style="color: red">красный текст</span>`.
Заданные вручную `id` сохраняются, поэтому работают HTML-якоря.

```sh
mdread examples/html.md
```

Чтобы Markdown разбирался внутри блочного HTML, отделяйте его от тегов пустыми
строками, как в `examples/html.md`. В обратных кавычках и fenced code blocks
HTML остаётся исходным текстом. Автообновление работает и для HTML-разметки.
Относительные ссылки и изображения разрешаются так же, как в обычном Markdown.

Перед отображением HTML обрабатывается встроенной библиотекой
[DOMPurify 3.4.17](https://github.com/cure53/DOMPurify/tree/3.4.17).
Скрипты, обработчики событий, `javascript:`-ссылки, iframe и глобальные блоки
`<style>` удаляются. Используйте `style="…"` для оформления элементов.
Для работы не нужны npm или подключение к CDN.

Сервер отдаёт Markdown-документы, свои стили/скрипт и изображения.
В режиме одного файла открывается только переданный документ, без боковой панели.

## Проверка

Проверки установочного скрипта на macOS (нужен Python 3):

```sh
zsh -n mac_setup.zsh
python3 tests/mac_setup.py
```

Они используют подставные команды вместо установки системных пакетов:
проверяют выбор зависимостей, пути с пробелами, режим без установки,
отсутствие SDK, аргументы, остановку при ошибках и настройку `PATH` без дубликатов.
При включённом `BUILD_TESTING`
они также доступны в CTest под именем `mac_setup`. Сборка через `mac_setup.zsh`
отключает тесты в своём каталоге; для тестирования используйте ручную сборку ниже.

При наличии Python 3 CMake добавляет интеграционные тесты:

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=ON
cmake --build build
ctest --test-dir build --output-on-failure
```

Тесты запускают настоящий сервер и проверяют рендеринг, обновления, атомарное
сохранение, восстановление файла, доступ к изображениям, ограничения путей,
аргументы CLI и остановку по сигналу. Дополнительно проверяются списки директорий,
подпапки, пустые папки, имена с пробелами и специальными символами, обновление списка
и запрет выхода за пределы корня. Для тестов нужен доступ к локальным портам.

Для проверки самого окна на macOS в графическом сеансе:

```sh
cmake -S . -B build -DMDREAD_TEST_NATIVE_WINDOW=ON
cmake --build build
ctest --test-dir build --output-on-failure
```

Этот дополнительный тест открывает настоящее окно, проверяет документ в WKWebView,
его обновление после записи файла, сохранение прокрутки и закрытие окна.
Для режима директории проверяются нажатия на папку и файл, переход по Markdown-ссылке
и возврат в корень. Также проверяется завершение обычной команды с окном и сервером по `Ctrl+C`.
HTML-проверки в настоящем окне проверяют раскрытие `<details>`, встроенные стили,
изображения, сохранение HTML-якорей, переход по HTML-ссылке, отображение HTML-кода,
обновление документа и фильтрацию скриптов и обработчиков событий.

При включённых тестах окна проверка `math_sample` открывает `examples/formulas.md`
и проверяет наличие нижних индексов и отсутствие ошибок формул. Тем же тестовым
окном можно проверить свои файлы без их изменения:

```sh
python3 tests/math_corpus.py ./build/mdread ./build/mdread_window_test /путь/к/документу.md
```
