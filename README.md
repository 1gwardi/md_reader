# mdread

Ридер одного Markdown-файла на C++17 для macOS и Linux.

```sh
mdread notes.md
```

Команда открывает документ в отдельном окне приложения без адресной строки и вкладок.
После сохранения файла содержимое обновляется автоматически:
ридер проверяет изменения раз в 600 мс и сохраняет позицию прокрутки.
Закрытие окна завершает программу вместе с локальным сервером.
На macOS также работают `Cmd+W`, `Cmd+Q` и копирование текста через `Cmd+C`.
Остановка из терминала — `Ctrl+C`.

На macOS окно использует системные AppKit и WKWebView, на Linux — GTK 3 и WebKitGTK.
Разбор Markdown, CLI и локальный сервер написаны на C++17; системный интерфейс
macOS подключён небольшим модулем Objective-C++. Сервер слушает только `127.0.0.1`
на автоматически выбранном свободном порту. Внешние ссылки открываются
в браузере по умолчанию, оставляя документ в окне ридера.

## Сборка

Нужны C++17, CMake 3.16+ и [MD4C](https://github.com/mity/md4c).
На macOS нужны Command Line Tools (`xcode-select --install`), которые включают
системные SDK AppKit/WebKit. Дополнительная GUI-библиотека не требуется.
Во время работы программы интернет не требуется, стили и скрипт поставляются вместе с ней.

macOS (Homebrew):

```sh
brew install cmake md4c
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
./build/mdread examples/demo.md
```

Debian / Ubuntu:

```sh
sudo apt install build-essential cmake pkg-config libmd4c-dev libmd4c-html0-dev libgtk-3-dev libwebkit2gtk-4.1-dev
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
./build/mdread examples/demo.md
```

В новых выпусках Debian пакет заголовков HTML-рендерера называется
[`libmd4c-html-dev`](https://packages.debian.org/sid/libmd4c-html-dev)
вместо `libmd4c-html0-dev`.

Для команды `mdread` без пути установите бинарник в `~/.local/bin`:

```sh
cmake --install build --prefix "$HOME/.local"
export PATH="$HOME/.local/bin:$PATH"
mdread examples/demo.md
```

Строку `export PATH=...` можно добавить в `~/.zshrc` или `~/.bashrc`.
На macOS сборка проверена; Linux поддерживается исходным кодом, но пока не проверялся.

## Использование

```sh
mdread "путь/заметка с пробелами.md"
mdread --no-window notes.md           # Только сервер, без графического окна
mdread --port 8080 notes.md           # Выбрать порт вручную
mdread -- --file.md                   # Имя файла начинается с дефиса
mdread --help
```

`--no-window` подходит для запуска без графического сеанса и печатает локальный URL.
Старое имя этой опции, `--no-browser`, сохранено как синоним.

Поддерживаются заголовки, ссылки, изображения, цитаты, списки, таблицы,
зачёркивание, списки задач и блоки кода. Есть светлая и тёмная темы
по системным настройкам. Заголовкам назначаются якоря: `## Мой раздел` → `#мой-раздел`.
Подсветка синтаксиса и математические формулы пока не реализованы.

Относительные пути изображений считаются от папки открытого файла:
`![Схема](images/diagram.png)`. Доступны PNG, JPEG, GIF, WebP, SVG, AVIF и ICO
внутри этой папки и её подпапок. Ссылки наружу через `..` и симлинки запрещены.
Изменение самого изображения отобразится при следующем обновлении Markdown
или ручном обновлении страницы.

Файл перечитывается по содержимому, поэтому сохраняется поддержка редакторов,
которые заменяют файл целиком при сохранении. Если файл временно недоступен,
страница сохраняет последний текст и возобновляет обновления, когда файл появится.
Максимальный размер Markdown и каждого локального изображения — 16 MiB.

Встроенный HTML показывается как текст; скрипты из Markdown не выполняются.
Сервер отдаёт только открытый документ, свои стили/скрипт и изображения.
Список файлов и переходы к другим Markdown-файлам пока не реализованы.

## Проверка

При наличии Python 3 CMake добавляет интеграционные тесты:

```sh
ctest --test-dir build --output-on-failure
```

Тесты запускают настоящий сервер и проверяют рендеринг, обновления, атомарное
сохранение, восстановление файла, доступ к изображениям, ограничения путей,
аргументы CLI и остановку по сигналу. Для них нужен доступ к локальным портам.

Для проверки самого окна на macOS в графическом сеансе:

```sh
cmake -S . -B build -DMDREAD_TEST_NATIVE_WINDOW=ON
cmake --build build
ctest --test-dir build --output-on-failure
```

Этот дополнительный тест открывает настоящее окно, проверяет документ в WKWebView,
его обновление после записи файла, сохранение прокрутки и закрытие окна.
Также проверяется завершение обычной команды с окном и сервером по `Ctrl+C`.
